## TLDR;

<img src="https://mindx.edu.vn/logo.svg" alt="MindX Logo" class="mindx-logo" />

1. **CV:** Clean format, Skills at top, Education before Experience (entry-level), achievements with metrics, always include links
2. **Live Coding:** Be humble, ask questions immediately, handle first then optimize, ask for feedback after completing
3. **Template:** FAANGPath LaTeX Template - ATS-compliant, clean design (link in CV Structure slide)

### Critical Requirements

- Clean, tidy format
- Single-column layout
- PDF format
- Avoid page breaks mid-section

**Most companies use AI screening** - ATS (Applicant Tracking System) optimization is critical

### Recommended Order

1. Contact info
2. Professional summary (2-3 lines, concise) - *can be placed before Skills*
3. **Skills** with ratings (0-5)
4. **Education** ← *Place before Experience for entry-level*
5. Work experience / Internships
6. Projects with links
7. Optional: Certifications

**Note:** For entry-level candidates with limited experience/projects, Education comes before Experience to highlight qualifications and coursework.

**Template:** [FAANGPath LaTeX Template](https://www.overleaf.com/latex/templates/faangpath-simple-template/npsfpdqnxmbc) - ATS-compliant, clean design, easy to customize

### X-Y-Z Formula

**"Accomplished [X] as measured by [Y], by doing [Z]"**

**Example:**
"Reduced API latency by 45% by implementing Redis caching and optimizing PostgreSQL queries, serving 2M+ daily requests"

### Key Points

- Focus on achievements with numbers/metrics
- Brief descriptions are sufficient
- Always include links (GitHub or live products)

### Attitude

- **Be humble** - Ready to accept feedback
- **Ask questions** - Immediately when receiving problem
- **Handle first** → Optimize later
- **After completing:** Ask for feedback, ask about team/work

**Humility and curiosity show cultural fit**

### Step-by-Step

1. **Ask questions** - Understand problem clearly
2. **Think out loud** - Explain approach before coding
3. **Handle first** - Get working solution
4. **Consider edge cases** - Empty inputs, single elements
5. **Test solution** - Walk through examples
6. **Optimize** - Improve time/space complexity

**Don't rush - thought process matters more than perfect solution**
